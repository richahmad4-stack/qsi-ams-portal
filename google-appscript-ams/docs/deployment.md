# Google Apps Script AMS Deployment

## Architecture

The application is a Google Apps Script web app using:

- `HtmlService` for the web interface.
- `Jdbc.getCloudSqlConnection` for Cloud SQL MySQL.
- `Session.getActiveUser().getEmail()` for Google Workspace identity.
- `DriveApp`, `DocumentApp`, and PDF export for controlled document outputs.
- Script Properties for environment configuration.

## Cloud SQL

Create a MySQL database and run:

```sql
source sql/schema_cloudsql.sql;
```

Create a least-privilege application user with access to the AMS database. Do not use the root account in Script Properties.

## Apps Script

Create a standalone Apps Script project and add:

- `appsscript.json`
- `Code.gs`
- `Index.html`

Set Script Properties:

```text
CLOUD_SQL_CONNECTION_NAME=project:region:instance
DB_NAME=qsi_ams
DB_USER=ams_app
DB_PASSWORD=...
AMS_ROOT_FOLDER_ID=...
AMS_PUBLIC_BASE_URL=https://script.google.com/macros/s/.../exec
AMS_DEV_USER_EMAIL=admin@example.com
```

Deploy as a versioned Web app:

- Execute as: `User accessing the web app`
- Access: Workspace domain users

After the schema is installed, open the deployed URL. If no AMS users exist yet, the error screen includes `Seed baseline / create first admin`; it seeds tenant, roles, permissions, standards, templates, audit requirements, and creates the active Google user as `super_admin`. If Apps Script cannot expose the active user email during testing, set `AMS_DEV_USER_EMAIL` before this bootstrap step.

## Controlled Document Output

Documents are written into `AMS_ROOT_FOLDER_ID` under per-client folders. Each generated document is recorded in `generated_documents` with:

- source record
- Drive file ID
- PDF file ID
- version number
- hash surrogate
- generated by
- generated at

## Security Notes

- Google identity is the login layer; no Apps Script password form is used.
- Every server action calls `requirePermission`.
- Writes are recorded in `audit_logs`.
- The UI hides disallowed actions, but the server remains the enforcement point.
- Do not publish the web app to `Anyone` for live AMS use.

## Migration Notes

Recommended migration order:

1. Tenants, roles, permissions, users.
2. Standards and master data.
3. Clients and client standards.
4. Applications and reviews.
5. Audit programmes, events, appointments, and plans.
6. Report responses, findings, NCR/CAPA.
7. Technical review, decisions, certificates.
8. Finance, documents, audit logs.

For historical records, import in preview batches and keep source file names, row numbers, hash values, and review status in `legacy_import_rows`.
